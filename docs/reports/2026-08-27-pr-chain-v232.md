## #22 — web paywall guard

Found while reviewing #20. Pre-existing on `main`, unrelated to any open PR.
`_purchasePlus` short-circuited on any non-native platform:

```js
if (!window.Capacitor?.isNativePlatform?.()) {
  _setPlusSub(true);          // any visitor, for free
  return { success: true, web: true };
}
```

A dev-testing affordance that also shipped to production. #20 would have made
that button more prominent, so this was sequenced first.

**Fix, two parts.** (1) Hostname allowlist (`localhost` / `127.0.0.1` /
`*.local`), mirroring the existing `_appleMusicOriginOk()` precedent in
`spotify-api.jsx`. Off a dev host the purchase returns
`{success:false, unsupported:true}` and grants nothing. (2) The UI stops
advertising a price it cannot charge — on web the paywall drops the price
button, the auto-renew disclosure, and RESTORE (`_restorePurchases` already
returned `"Web mode"` off-native and could only ever fail), showing
"Plursky+ is available in the iOS app" + a GET THE APP link instead.

Also fixed a conditional hook: `PlusGate` called `React.useState` *after*
`if (_isPlusSub()) return children`.

Both branches executed in real Chrome, production host simulated with
`--host-resolver-rules="MAP plursky.com 127.0.0.1"`:

| | localhost | plursky.com |
|---|---|---|
| `_purchasePlus()` | success | `unsupported` |
| Plus granted after click | `true` (intended) | **`false`** |
| price / auto-renew / RESTORE shown | yes | **no** |
| GET THE APP shown | no | **yes** |

> Not a security boundary, and not claimed as one. Plus is a `localStorage`
> flag in a client-side app; anyone with a console can set it. This closes the
> path where the product's own UI gives it away to an ordinary visitor. Real
> enforcement is StoreKit/RevenueCat on native.

## #20 — season pass IAP

`plursky_season_pass_2026` ($14.99 non-consumable) primary,
`plursky_plus_monthly` ($4.99/mo) secondary. The $7.99/yr annual stays defined
in code and in ASC but is pulled from the RevenueCat offering — existing buyers
hold the same `plus` entitlement, so zero migration code.

**Guideline 3.1.2** — disclosures are split deliberately. The season pass is a
non-consumable, so auto-renew copy on it would be a rejection. Its line reads
*"one-time purchase. No subscription, nothing auto-renews"* — not "for the 2026
season", because a non-consumable never expires. Monthly keeps the existing
disclosure verbatim with only the price swapped. Terms/Privacy render once.

**The #22 conflict was real, not just a version bump.** #22 wrapped the paywall
in `{canBuy ? … : …}`; #20 replaced that block's single button with two.
Resolution nests both buttons, both disclosures, Terms·Privacy and RESTORE
inside the `canBuy` branch. Worth recording: the resolution forced **both**
`useState` calls above the early return — had `pending` stayed below it, the
merge would have silently re-introduced the exact conditional-hook bug #22 had
just fixed.

**Judgment call, made against instruction.** A crew-chat promo card
(`supabase.jsx:2218`) advertised `$4.99 / festival` — matching no product that
exists. The instruction was to correct it to `$2.99 / festival`, but
`docs/SPEC-season-pass-1499.md` lines 13–14 confirm `plursky_plus_festival` is
deferred: never created in ASC, never in the offering. $2.99 is as unbuyable as
$4.99. Under the stated principle *"no phantom prices ship"*, letter and intent
pointed opposite ways; went with intent. The card now reads
`$14.99 · SEASON PASS`, mirroring the paywall's primary CTA. One string,
trivially reverted.

## #21 — SEO indexing

plursky.com is a client-rendered SPA on GitHub Pages, so crawlers saw an empty
`<div id="root">`. Nothing on the site was indexable.

Added `robots.txt`; `sitemap.xml` (10 URLs); seven static stubs at `/f/<slug>/`
generated by `scripts/gen-festival-pages.mjs`; a static semantic shell inside
`#root` with a matching `<noscript>`; `rel=canonical`; WebSite + Organization
JSON-LD; a `?f=<id>` deep link; OG/Twitter + `noindex,nofollow` on `share.html`.

Two things that weren't obvious going in:

1. **`share.html` had to be excluded.** Each of those URLs is somebody's *live
   location* — indexing one would publish it. It is `noindex,nofollow`,
   `Disallow`-ed, and absent from the sitemap.
2. **`?f=` was not the two-liner it looked like.** `getActiveFestivalId()` only
   honours a stored id when the festival is `available`. Writing a **gated** id
   and reloading leaves the active festival unchanged with `?f=` still in the
   URL — so the next boot switches again, forever. Four of seven registry
   entries are gated, so that was the common path, not an edge case. The
   handler now only switches when the festival would stick, skips when already
   active, and strips the param before reloading. All seven entries verified
   loop-free.

Lineup depth: full where a lineup is published, teaser where none exists. No
set times or stage assignments on any stub.

| stub | performers | | stub | performers |
|---|---|---|---|---|
| edc-lv-2026 | 241 | | edc-orlando-2026 | 109 |
| electric-forest-2026 | 118 | | tomorrowland-2026 | 0 (teaser) |
| lost-lands-2026 | 201 | | coachella-2027 | 0 (teaser) |
| acl-2026 | 130 | | | |

Every stub's JSON-LD parsed with a real JSON parser (all `MusicFestival`,
correct canonical + startDate); `sitemap.xml` parses with the correct
`sitemaps.org` namespace; crawler view with JS disabled returns 23,990 bytes
and 209 `<li>` for Lost Lands; post-boot `#root` holds 19,433 chars of rendered
DOM with **zero** `.boot-shell` nodes surviving (the only copy left is inside
`<noscript>`) — React genuinely replaces the shell, so not cloaking;
`?f=acl-2026` flips the render from "241 artists across 9 stages" to
"130 artists across 10 stages".
