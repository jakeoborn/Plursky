## Checks

### 1. ⭐ Favorite (v207)
- Open any moment in the lightbox → tap the **★ star** (top bar, next to the
  `n / n` counter). It should fill **gold** and a light haptic should fire.
- Close + reopen → star is still gold (persisted).
- Go to **GRID** → the favorited photo shows a small gold ★ badge (top-left).
- Go to **NIGHT** → that moment's group should now lead with the favorited shot
  as its cover thumb (favorite wins the hero pick).
- **PASS:** star toggles + persists + badge shows + becomes the group cover.

### 2. Peak 20-min card (NIGHT lens)
- Open **NIGHT**. Under each night's header, a **"YOUR PEAK · 20 MIN"** card
  should appear (only when that night has ≥3 located moments).
- Check the count + clock range look right ("9 moments in 20 minutes",
  "12:20 AM – 12:39 AM").
- Tap **▶ RELIVE** → it should play a reel of *just that 20-min window*.
- Tap a thumb in the card's strip → opens the lightbox at that shot.
- **PASS:** card appears on dense nights, numbers are sane, RELIVE + thumbs work.
- **Watch for:** wrong/garbled times (timezone), card showing on a 1–2 moment
  night, RELIVE playing the whole night instead of the window.

### 3. Burst stacking (GRID lens)
- Open **GRID**. A run of photos shot within ~4s of each other (same artist)
  should collapse into **one tile** with a **`⧉ N`** badge + a stacked-card edge.
- Tap a stacked tile → lightbox opens; **swiping** should move through the
  burst's siblings (and on through the rest of the grid).
- **PASS:** bursts collapse, badge count matches, swipe still reaches every shot.
- **Watch for:** unrelated photos wrongly merged; the stack shadow colliding
  with the neighbour tile; count off by one.

### 4. Map lens (new MAP lens)
- Open **MAP**. The festival basemap renders with a **count-pin per stage** you
  shot at, sized by how many moments, plus a tappable **legend chip** row below.
- Tap a pin **and** a legend chip → both open that stage's moments in the lightbox.
- **On the physical device** (real GPS photos): pins should land on the right
  stages. On simulator/untagged data, pins fall back to the tagged artist's stage.
- **PASS:** basemap image loads, pins + legend tap through correctly.
- **Watch for:** blank/black map (basemap image not loading), pins stacked in
  one corner (projection wrong), "NO LOCATED MOMENTS" when moments are tagged.

### 5. Night scrubber (STORY lens)
- Open **STORY**, pick a night. Above the beats there's a **time-track** with a
  tick per moment (gold tick = a favorite).
- **Drag** along it → a preview thumb + clock should follow your finger and snap
  to the nearest moment; **release** opens that moment in the lightbox.
- **PASS:** drag feels smooth, preview tracks correctly, release opens the right
  shot. (This is the one most worth feeling on a real touch screen.)
- **Watch for:** janky/laggy drag, preview thumb off-screen at the edges, release
  opening the wrong moment.

### 6. Shazam-from-video (v206 native fix — STILL OWED)
- **Physical device only.** Open a **video** moment → tap **"🎵 IDENTIFY THE SONG
  FROM THIS VIDEO."**
- **PASS:** it returns a real song match (not "NO MATCH — TRY A LOUDER CLIP") and
  the moment shows a "SHAZAMED" song line afterward.
- This is the v206 `SHSignatureGenerator` fix in `ShazamPlugin.swift`, never yet
  verified on a real phone. If it still says NO MATCH on a clip with clear audio,
  file an issue with the clip details (length, how loud).

### 7. Signed-in backup round-trip (Plus)
- **Physical device, signed in.** Memories → **"Back up my weekend"** (and/or the
  auto-backup toggle). Let it run.
- **PASS:** upload completes without error; then on a fresh load / second device,
  the backed-up media restores on view. Watch the per-moment byte tracking +
  the 1GB soft / 2GB hard cap behaviour.
- **Watch for:** upload hangs/errors, restore not pulling media, cap miscounting.

## 8. Archive + submit `1.9 (20)` (Jake / Clicky in Xcode)

This is a GUI/signing step Claude Code can't drive — it lives with whoever's at
the Xcode screen. The repo side is already done: `project.pbxproj` is at
**MARKETING_VERSION 1.9 / CURRENT_PROJECT_VERSION 20** (commit `393f5bd`), and
the v208 web bundle is synced into `ios/App/App/public`. **Run the smoke checks
1–7 above on the build first — only archive once they pass.**

Canonical flow is in `RELEASE.md`; the Xcode clicks:
1. Open **`ios/App/App.xcworkspace`** (the workspace, not the project).
2. Confirm the synced bundle is current: **Product ▸ Clean Build Folder**, then
   pick a real device (or **Any iOS Device (arm64)**) as the run destination —
   you can't archive against a simulator.
3. **Product ▸ Archive.** When the Organizer opens, select the new archive.
4. **Distribute App ▸ App Store Connect ▸ Upload.** Let it auto-manage signing.
5. In App Store Connect, attach build **`1.9 (20)`** to the version, fill
   "What's New", submit for review.

**Guardrails (from `CLAUDE.md`):** the marketing string must be numerically
higher than the last approved (`1.8` → `1.9` ✓, NOT `1.0.x`), and the build
number must be unique/higher than 19 (`20` ✓). If the upload rejects on version
(err 90062/90478), it's a number lower-or-equal to what's live — stop and tell
Claude Code to re-bump `project.pbxproj`; don't hand-fix it in Xcode (it'd drift
from the repo).
